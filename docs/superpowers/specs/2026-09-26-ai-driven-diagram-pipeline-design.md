# AI 主导 Diagram DSL 的设计

## 目标

自然语言、Markdown/TXT/PDF/DOCX 文档、PNG/JPEG/WebP 图片以及已有 `.model.json` 或参考图片，都能作为 AI 规划图表的输入。模型决定图的类型、节点、容器和关系；现有 DSL、ELK、验证器和渲染器负责其余阶段。规则解析器仅在明确指定 `--offline` 时使用，示例工厂仅用于 `--examples` 和 `--preset`。

## 输入与配置

CLI 的 `generate` 支持 `--text`、`--document`、`--image` 三种主输入，以及可选 `--template`。模板可为 `.model.json` 或 PNG/JPEG/WebP 参考图片；单独的模板不是生成请求。文档提取正文，限制文件大小和文本长度；图片以 data URL 发给支持视觉的模型。模型走 OpenAI 兼容 Chat Completions 接口，由 `DIAGRAM_AI_API_KEY`、`DIAGRAM_AI_MODEL`、`DIAGRAM_AI_BASE_URL` 配置。缺少配置、格式不支持或 API 失败时返回错误，不落盘。

## 规划契约

模型返回 `SemanticPlan`：`diagram`、`confidence`、`uncertainties`。每个节点、边和容器都有 `provenance`，包含来源、证据片段和元素置信度。文本、文档、JSON 模板的证据片段必须逐字出现在对应输入中；图片证据由视觉模型报告，并在质量报告中标为未被程序独立核实。要求至少两个节点、一条关系、全部元素有证据、整体及元素置信度达到 0.7、无阻断性不确定项。模型输出的 `x/y`、布局边路由和 Draw.io XML 均被拒绝。模型不得借内置示例补齐未知业务语义。

## 验证与修正

每次规划先做 Schema/证据检查和现有语义检查，再单独调用模型复核原始输入中的遗漏和无依据元素；通过后由 ELK 最多执行 5 轮布局并产出布局问题。若有可修正的语义或布局问题，将结构化反馈交给模型重新规划，最多进行 3 次模型规划。修正时保留未修改元素的稳定 ID。语义检查仍失败时不输出任何图；布局达到上限仍失败时允许输出图和质量报告，但 CLI 返回非零码且明确列出错误。质量报告记录来源、规划与复核置信度、模型规划次数、证据核验状态、语义与布局问题。

## 输出与限制

成功时生成 `.model.json`、`.drawio`、`.svg`、`.quality.json`。输入内容不会写进日志，API key 不写进文件。图片内容理解和文档需求是否遗漏目前仍依赖视觉/语言模型；证据核验只能证实引用确实来自输入，不能证明模型理解正确。用户可检查质量报告与可编辑 DSL。没有模型配置时使用 `--input`、`--offline` 或显式预设。

## 验证

用 mock provider 覆盖成功规划、低置信度、无证据、错误引用、修正次数和无输出副作用；用 CLI 测试配置缺失与输入选项；用文档/图片适配器测试格式校验。最后运行 build、test、examples，保留现有示例和工作区已有改动。
